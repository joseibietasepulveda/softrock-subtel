Usuarios y roles

Roles: Regular (carga, trabaja y envía a aprobación) · operador (carga y revisa sus documentos) · revisor (revisa todos) · aprobador (revisión avanzada) · auditor (solo lectura de bitácora) · administrador (todo). Con LDAP/AD habilitado, los usuarios del directorio ingresan directamente y su rol proviene del mapeo de grupos.

Políticas por tipo documental

Define qué datos se tachan según el tipo de documento (fila * = valor por defecto). Ej.: en un contrato tachar RUT pero no fechas. La política se aplica al cargar; el usuario puede ajustar el desplegable en cada carga.

Integración API

Los sistemas de SUBTEL pueden tachar documentos vía REST con un token Bearer. Documentación interactiva en /docs.

# Tachado directo (sin revisión):
curl -H "Authorization: Bearer stk_..." -F "file=@resolucion.pdf" \
  -F "document_type=resolucion" -F "analysis_level=exhaustivo" -F "treatment=anonymize" \
  -o resolucion_protegida.pdf http://SERVIDOR:8000/api/v1/redact

# Las mismas opciones que la plataforma (código o nombre, con o sin tilde):
#   analysis_level  fast | balanced | exhaustive   (rápido | equilibrado | exhaustivo)
#   treatment       redact | anonymize | pseudonymize | mask_full | mask_partial
#   document_type   aplica la política del tipo documental (GET /api/document-types)
#   entities        opcional, reemplaza la política: NOMBRE,RUT,EMAIL (GET /api/v1/entity-types)
# Los PDF protegidos se entregan como PDF/A-1b.

# Masivo desde buckets (URL prefirmadas, sin revisión humana; ver README):
curl -H "Authorization: Bearer stk_..." -H "Content-Type: application/json" \
  -d '{"options": {"analysis_level": "equilibrado", "treatment": "anonimizar"},
       "items": [{"source_url": "https://bucket/orig.pdf?firma", "target_url": "https://bucket/anon.pdf?firma"}]}' \
  http://SERVIDOR:8000/api/v1/jobs          # → job_id; estado en GET /api/v1/jobs/{job_id}

# Flujo con revisión: POST /api/v1/documents → GET .../findings → PATCH … → POST .../approve → GET .../protected

Acerca de esta versión (0.6.0)

Incluido

  • Carga individual, múltiple y ZIP; lotes con ZIP y reporte CSV
  • 15 tipos de datos sensibles, incl. firma manuscrita (heurística)
  • Revisión humana por hallazgo: aceptar, rechazar, agregar manual (rectángulo o selección de texto)
  • Flujo de aprobación administrativa para usuarios Regular
  • Políticas por tipo documental (matriz editable)
  • Cinco tratamientos: tachado, anonimización, seudonimización y enmascaramiento total o parcial
  • Verificador posterior: revisa el resultado e informa las alertas antes de descargar
  • Autenticación Keycloak, LDAP / Active Directory y cuentas locales
  • Bitácora inalterable con tratamiento, API REST y protección en 11 formatos
  • PDF de entrada y salida en formato PDF/A (salida PDF/A-1b)
